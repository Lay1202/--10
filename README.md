# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반 / 조기 종료), 삽입 정렬(`>` / `>=`)을 C로 구현하고, 비교 횟수·데이터 이동 횟수·안정성을 측정했습니다.
전체 실행 로그는 `result.txt`에 있습니다.

- 빌드: `gcc -O2 -o sort_compare sort_compare.c`
- 실행: `./sort_compare`
- 난수: 이식성을 위해 자체 xorshift64* 생성기를 사용했고 시드를 고정했기 때문에 실행할 때마다 같은 결과가 나옵니다.

## 1. 구현 및 측정 기준

| 항목 | 기준 |
|---|---|
| 데이터 | `(key1, key2, order)` 구조체. `order`는 원래 입력 순서로 안정성 검증에만 쓰고 정렬 기준에는 쓰지 않습니다. |
| 비교 횟수 | 두 데이터의 `key1`을 비교할 때마다 1회. 루프 인덱스 비교는 제외합니다. |
| 이동 횟수 | 데이터 전체의 복사·대입 1회 = 1. 교환은 `temp` 사용으로 3회입니다. |
| 선택 정렬 | 최솟값 위치가 현재 위치와 같으면 교환하지 않습니다(이동 0회). |
| 삽입 정렬 | `current` 임시 저장 1회 + 한 칸 이동 1회씩 + 최종 위치 대입 1회를 모두 계산합니다. 그래서 정렬된 데이터에서도 원소당 2회, 총 2(N-1)회가 발생합니다. |
| 제외 항목 | 원본 복사, 데이터 생성, 시험 입력 준비용 사전 정렬(`qsort`)은 카운트하지 않습니다. 정렬 알고리즘 자체에는 라이브러리 정렬을 쓰지 않았습니다. |
| 공정성 | 모든 알고리즘은 같은 원본의 복사본으로 실행하며, 정렬 후 오름차순 여부와 입력의 순열 여부를 검증합니다. |

## 2. 무작위 데이터 100회 실험 (N = 10,000)

| 알고리즘 | 총 비교 횟수 | 평균 비교 횟수 | 평균 이동 횟수 |
|---|---:|---:|---:|
| 선택 정렬 | 4,999,500,000 | 49,995,000.00 | 29,970.45 |
| 버블 정렬 | 4,999,500,000 | 49,995,000.00 | 74,964,148.86 |
| 버블 정렬 (조기 종료) | 4,998,594,885 | 49,985,948.85 | 74,964,148.86 |
| 삽입 정렬 (`>`) | 2,499,803,970 | 24,998,039.70 | 25,008,047.62 |

100회 모두 올바르게 정렬되었습니다.

**일반 버블 vs 조기 종료 버블.** 조기 종료 버블의 비교 횟수는 일반 버블보다 총 905,115회(평균 약 9,051회, 약 0.018%) 적었습니다. 무작위 데이터에서는 거의 끝까지 교환이 발생하기 때문에 조기 종료 조건이 거의 작동하지 않습니다. 마지막 몇 번의 순회만 줄어들고, 이동 횟수는 두 방식이 완전히 같습니다. 교환이 일어나는 횟수는 역전 쌍(inversion)의 개수로 정해지기 때문입니다.

**원인 분석**
- 선택 정렬은 입력과 상관없이 항상 N(N-1)/2 = 49,995,000회를 비교합니다. 최솟값을 찾으려면 남은 구간을 끝까지 훑어야 하기 때문입니다. 교환은 많아야 N-1번이라 이동이 적습니다(평균 약 3만 회).
- 버블 정렬의 이동 횟수는 3 × (역전 쌍 수)입니다. 무작위 데이터의 역전 쌍은 평균 N(N-1)/4 ≈ 2,500만 개이므로 이동은 약 7,500만 회로 4개 중 가장 많습니다.
- 삽입 정렬은 역전 쌍 수에 비례하는 만큼만 비교·이동하므로 비교가 선택·버블의 절반 수준(약 2,500만 회)입니다. 이동은 (역전 쌍 수) + 2(N-1)이라 약 2,500만 회입니다.

## 3. 입력 정렬 상태별 성능

정렬·역순·부분 정렬 데이터는 모두 무작위 실험 1회차의 원본 데이터에서 만들었습니다.

| 입력 상태 | 알고리즘 | 비교 횟수 | 이동 횟수 |
|---|---|---:|---:|
| **정렬됨** | 선택 | 49,995,000 | 0 |
| | 버블 | 49,995,000 | 0 |
| | 버블 (조기 종료) | 9,999 | 0 |
| | 삽입 | 9,999 | 19,998 |
| **역순** | 선택 | 49,995,000 | 15,066 |
| | 버블 | 49,995,000 | 149,984,856 |
| | 버블 (조기 종료) | 49,995,000 | 149,984,856 |
| | 삽입 | 49,995,000 | 50,014,950 |
| **일부 정렬** | 선택 | 49,995,000 | 1,503 |
| | 버블 | 49,995,000 | 9,050,718 |
| | 버블 (조기 종료) | 49,978,529 | 9,050,718 |
| | 삽입 | 3,026,905 | 3,036,904 |

### 일부 정렬 데이터 생성 방법 및 AI 활용
- **방법:** 정렬된 데이터에서 무작위 두 위치를 골라 서로 바꾸는 작업을 N/20 = 500번 반복했습니다. 전체의 5%에 해당하는 교환을 가한 것이고, 최대 약 1,000개 원소가 제자리를 벗어납니다. 나머지 90% 이상은 원래 위치에 남아 있습니다.
- **AI 활용:** 이 방법은 AI에게 "정렬된 데이터에 소수의 무작위 교란을 가하는 방식"을 조사·설계하게 하여 선택했습니다. 교환 횟수 5%는 임의로 정한 값이므로, 직접 다른 비율로 바꿔 실험하고 이 부분을 본인 표현으로 고쳐 쓰는 것을 권장합니다. (교환 횟수는 코드의 `SWAP_COUNT`로 바꿀 수 있습니다.)

### 상태별 분석
- **이미 정렬된 데이터**
  - 선택 정렬과 일반 버블은 입력과 무관하게 모든 쌍을 비교하므로 49,995,000회로 무작위 때와 같습니다. 이동은 교환이 필요 없어 0회입니다.
  - 조기 종료 버블은 첫 순회(9,999회 비교)에서 교환이 없으면 바로 끝납니다. 비교가 약 5,000분의 1로 줄어드는 가장 효과적인 경우입니다.
  - 삽입 정렬은 원소마다 바로 앞 원소와 1번만 비교하고 끝나므로 비교가 N-1 = 9,999회입니다. 이동은 임시 저장 1회와 최종 대입 1회로 원소당 2회, 총 19,998회입니다. 구현상 실제 이동이 없어도 이 두 번은 카운트됩니다.
- **역순 데이터**
  - 모든 쌍이 역전이어서 버블(149,984,856 = 3 × 49,995,000)과 삽입(약 5천만 회)이 모두 최악이 됩니다.
  - 매 순회마다 교환이 발생하므로 조기 종료 버블도 이점이 전혀 없어 일반 버블과 같은 값이 나옵니다.
  - 선택 정렬은 비교는 최대이지만 교환이 약 N/2번(15,066 ≈ 3 × 5,022)뿐이라 이동이 매우 적습니다. 이동 비용이 큰 환경에서는 선택 정렬이 유리할 수 있습니다.
- **일부 정렬 데이터**
  - 삽입 정렬은 비교 3,026,905회, 이동 3,036,904회로 무작위 대비 약 8분의 1로 줄었습니다. 역전 쌍이 적을수록 성능이 좋아지는 적응적(adaptive) 성질 때문입니다.
  - 버블 이동도 약 905만 회로 무작위의 1/8 수준이지만, 일반 버블은 비교가 그대로 49,995,000회입니다.
  - 조기 종료 버블은 교란된 원소가 제자리로 돌아올 때까지 순회가 계속되어 비교가 49,978,529회로 거의 줄지 않았습니다. 교환이 마지막 몇 순회까지 이어지면 조기 종료의 이득이 작습니다. 즉 이 조건은 "거의 완전히 정렬된" 데이터에서만 크게 효과가 있습니다.
  - 선택 정렬은 비교는 그대로이고 이동만 1,503회로 줄었습니다.

## 4. 안정성 검증

### 검증 방법
각 데이터에 원래 입력 순서(`order`)를 저장해 두고, 정렬 후 `key1`이 같은 인접 데이터 중 `order`가 뒤집힌 경우(앞의 `order` > 뒤의 `order`)의 개수를 셉니다. 이 개수(위반 횟수)가 0이면 안정, 1 이상이면 불안정으로 판정합니다.

### 검증에 사용한 입력 데이터
1. 과제 예시 4개: `(527,100)#0, (527,200)#1, (125,300)#2, (892,400)#3`
2. 중복이 많도록 `key1`을 0~49로 제한하고 `key2`는 무작위로 만든 1,000개 데이터. 무작위 10,000개 데이터는 중복이 적어서 별도로 만들었습니다.

### 결과

| 알고리즘 | 4개 예시 결과 | 4개 위반 수 | 1,000개 위반 수 | 판정 |
|---|---|---:|---:|---|
| 선택 정렬 | `(125)#2 (527,200)#1 (527,100)#0 (892)#3` | 1 | 325 | **불안정** |
| 버블 정렬 | `(125)#2 (527,100)#0 (527,200)#1 (892)#3` | 0 | 0 | **안정** |
| 버블 (조기 종료) | 버블과 동일 | 0 | 0 | **안정** |
| 삽입 (`>`) | `(125)#2 (527,100)#0 (527,200)#1 (892)#3` | 0 | 0 | **안정** |
| 삽입 (`>=`) | `(125)#2 (527,200)#1 (527,100)#0 (892)#3` | 1 | 950 | **불안정** |

(모든 경우에 정렬 자체는 올바르게 수행됨)

### 원인
- **선택 정렬:** 최솟값 `(125,300)`을 맨 앞과 교환하면서 맨 앞에 있던 `(527,100)`이 멀리 떨어진 위치로 날아갑니다. 이 과정에서 같은 키 `(527,200)`을 건너뛰기 때문에 같은 키끼리의 상대 순서가 깨집니다. 즉 먼 거리의 교환이 불안정성의 원인입니다.
- **버블 정렬:** 인접한 두 원소를 `>`일 때만 교환하므로 같은 키는 서로를 추월하지 않습니다. 따라서 안정입니다. 조기 종료는 순회를 멈추는 시점만 바꿀 뿐 교환 규칙을 바꾸지 않으므로 안정성에 영향이 없습니다.
- **삽입 정렬:** `>`는 같은 키를 만나면 이동을 멈추므로 새 원소가 같은 키 뒤에 들어가 순서가 유지됩니다(안정). 반면 `>=`는 같은 키도 계속 밀어내고 그 앞에 삽입하기 때문에 같은 키 그룹의 순서가 정확히 뒤집힙니다(불안정).

### 삽입 정렬 `>` vs `>=`
- 1,000개 중복 데이터에서 `>`는 비교 256,269회·이동 257,271회, `>=`는 비교 266,128회·이동 267,146회였습니다.
- `>=`는 같은 키 데이터도 불필요하게 이동시키므로 비교·이동이 모두 더 많고 안정성까지 잃습니다. 따라서 삽입 정렬은 `>`를 쓰는 편이 낫습니다.

## 5. 종합 정리
- 비교 횟수 기준으로 선택·일반 버블은 입력과 무관하게 항상 약 5천만 회로 같고, 입력 상태에 반응하는 것은 조기 종료 버블과 삽입 정렬뿐입니다.
- 데이터가 정렬에 가까울수록 삽입 정렬이 가장 크게 이득을 보고, 역순이면 모든 알고리즘이 최악에 가깝습니다. 다만 선택 정렬은 이동 횟수가 가장 적다는 장점이 있습니다.
- 안정 정렬이 필요하면 버블 정렬이나 `>`를 사용한 삽입 정렬을 쓰고, 선택 정렬은 피해야 합니다.
